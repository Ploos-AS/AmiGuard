Inspection notes (2026-09-06):
- GCC normalizes -m68000 to -mcpu=68000; assembler receives -m68000.
- Multilib directory is '.', not libm020. No FPU/JIT/68020 target selected.
- No unresolved symbols from nm -u. HUNK is a LoadSeg executable, not ELF.
- The native program calls C printf/puts. It has no DOS VPrintf/Printf call.
- nix13 includes local compatibility functions named AllocVec, FreeVec,
  GetProgramName, SelectInput and SelectOutput. These names are NOT calls to
  the corresponding V36 ROM vectors. For example AllocVec uses Exec AllocMem
  (-198), FreeVec uses FreeMem (-210), and SelectInput/SelectOutput access
  process fields. Checked in the disassembly generated for the tested binary.
- DOS calls in the inspected runtime use pre-V36 vectors (Open/Close/Read/
  Write/Input/Output/Seek/Lock/UnLock/DupLock/CurrentDir/IoErr/IsInteractive).
  Memory allocator semaphore calls are V33, supported by Kickstart 1.2.
- trackdisk.c sets CMD_READ=2, length=1024, offset=0; calls OpenDevice,
  DoIO, CloseDevice and releases its request/port. No CMD_WRITE/TD_FORMAT,
  raw-write, repair or bootblock rewrite path exists in this program.
- DoIO success plus io_Actual==1024 is required before the success message.
  Host tests reject short/zero transfers and check error cleanup.
- Full objdump output is in disassembly.txt. Strings reside in .text and are
  also decoded by objdump; these are not evidence of executed 68020 opcodes.
- Actual startup, errors and scanning on visible cycle-exact 68000 complement
  this static check. This is not an exhaustive proof for all unreachable code.
